# Exercise Templates — Grammar8r

Эталонные форматы для 14 типов хардкодных упражнений.  
При написании нового упражнения — **ЖЁСТКО** сверяться с этим файлом.

## ⚠️ КРИТИЧНО: габариты табличных заданий (CATEGORIZATION · MATCHING · TABLE_FILL)

Эти три типа рендерятся как **«таблица + пул на одном экране телефона»** (колонки друг напротив
друга, поле рядом с подсказкой, элементы перетаскиваются из пула в колонки). Поэтому при написании
контента — **держать элементы КОРОТКИМИ**, чтобы таблица и пул целиком влезали на один экран:

- Элементы пула / ячеек — **короткие слова или сжатые фразы**, НЕ большие предложения.
- **CATEGORIZATION:** ситуации/слова короткие. Длинные описания вроде «Здание на другом конце улицы»
  раздувают пул — переписывать сжато («здание вдали», «гора за окном»).
- **MATCHING:** короткими держать **обе** стороны, включая левую (она хоть и закреплена, но в том же
  ряду). Не пары «длинная русская фраза ↔ длинная английская».
- **TABLE_FILL:** подсказка слева — короткая; до 7 строк (правило уже есть).
- Ориентир: всё задание (условие + таблица + пул) видно на одном экране; 2–4 строки переноса — норма,
  простыня с прокруткой — нет.

Рендер этих типов рассчитан на компактность. Если задание выбивается по длине — переписать короче.
(Дублируется в `CLAUDE.md` → «Контент теории и упражнений», чтобы правило было на виду при авторстве.)

## ⚙️ Эталонный MD-формат для конвертера (парсер-контракт)

> **Это контракт между MD и `tasks/tools/md_to_json.py`.** Пишешь упражнение строго по образцу
> своего типа — конвертер парсит его без правок. Образцы выверены по парсеру и приоритетно
> по оформлению **последних карточек** (они эталон). Отклонишься — упражнение распарсится криво.
> Ниже после `→` указано, в какие поля DB-таблицы это ложится.

**Общие правила (для всех типов):**
- Заголовок: `**Ex N · <ТочныйТип>** *(ID: X)*`. Тип — точно из таблицы счётчиков.
- Варианты ответа: строки на `- `; правильный — `- **текст** ✓`. Опция-прочерк — `- —`.
- **Выделение жирным в текстах заданий: `**…**`** (канон, июнь 2026). Нужно подсветить слово,
  часть слова или ОДНУ БУКВУ в условии (какое слово определять в Matching, что заменять в
  Transformation, ударная гласная `rec**o**rd`, окончание `walk**ed**`) — берём в `**…**`.
  Конвертер пропускает маркер как есть, UI рендерит Bold (общая утилита `**`→AnnotatedString,
  звёздочки текстом не показывать). smell.py: парные `**…**` — ок, непарные — запах.
  ⚠️ Не путать со СЛУЖЕБНЫМ жирным-маркером ответа: `Правильное предложение: **…**`
  (WordArrangement) и `→ **"…"**` (Transformation) — там жирный съедается парсером,
  правило выделения на эти места не распространяется.
- **`*Explanation:*` ОБЯЗАТЕЛЕН у КАЖДОГО упражнения** — одной строкой. Это фидбек, который
  показывается при ошибке; без него ученик не понимает, что не так. Без explanation — упражнение
  неполное (deep-чек ловит). **Писать просто `*Explanation:*`** (без «(при ошибке)»); легаси-форму
  `*Explanation (при ошибке):*` парсер тоже принимает, но в новом контенте — короткий вариант.
  ⚠️ Курсивом только ярлык: `*Explanation:* текст`, НЕ `*Explanation: текст*` (всю строку) — иначе не распарсится.
- `---` между упражнениями — визуальный разделитель, парсер его игнорирует (каждое упражнение = свой экран).
- Таблицы — `| … | … |` со строкой-разделителем `|---|`; первая строка таблицы = заголовок.

### TableFill → `taskDescription`, `rows[{hint, answer}]`, `explanation`
```
**Ex N · TableFill** *(ID: X)*
Задание: <одна строка>
| <подсказка> | Ответ |
| я | I |
*Explanation ...:* ...
```
До 7 строк. Первая строка таблицы (заголовок) пропускается. **Ровно 2 колонки:** подсказка и
**сам правильный ответ** во второй колонке (НЕ `___`-плейсхолдер). **НЕ** использовать 3-ю колонку
и **НЕ** выносить ответы в строку `*Answers:*` — ответ всегда прямо в таблице.

### MultipleChoice · CHOICE / FORWARD_CHOICE / REVERSE_CHOICE → `choiceType, prompt, contextRu, options[{text,isCorrect}], explanation`
```
**Ex N · MultipleChoice · FORWARD_CHOICE** *(ID: X)*
"<предложение>" (опц. контекст в скобках)
- Вариант
- **Правильный вариант** ✓
- Вариант
*Explanation ...:* ...
```
`prompt` = предложение в кавычках. Строки-инструкции («Переведи на русский:», «Выбери английский перевод:») парсер отбрасывает. Русский контекст можно дать строкой `RU: …` (парсер кладёт её в `contextRu`, рендерится второй строкой под предложением) или в хвостовых скобках `(...)` — обе формы равноценны. Подтип можно писать и без префикса `MultipleChoice ·` (просто `FORWARD_CHOICE`), но **писать с префиксом — предпочтительно**.

### TrueFalse → `statements[{en, ru, isTrue}]`, `explanation`
```
**Ex N · TrueFalse** *(ID: X)*
| # | EN | RU | Верно? |
| 1 | He go to work. | Он ходит на работу. | ✗ |
*Explanation ...:* ...
```
Ровно 5 строк. `✓` = isTrue:true, `✗` = false. Минимум 2 верных и 2 неверных.

### WordArrangement → `situationRu, correctSentence, words[], distractors[], explanation`

**ЭТАЛОН** (как Ex 324):
```
**Ex N · WordArrangement** *(ID: X)*
RU: Вера хочет купить новые кроссовки.
Правильное предложение: **Vera wants to buy new sneakers.**
| Слово | Лишнее? |
| wants | — |
| to | — |
| to buying | ✗ |
*Explanation ...:* ...
```
**Жёсткие правила:**
- Таблица — **2 колонки** `| Слово | Лишнее? |`. Перевод слов НЕ пишем: чипы перевод не показывают,
  пользователь зажмёт слово (long-press) и получит перевод сам.
- Промт: `RU: <перевод>` (или `Ситуация: <контекст>`). **НЕ** голая строка в кавычках.
- `Правильное предложение:` — **ЕДИНСТВЕННОЕ число** (предложение одно), ровно одно `**...**`,
  **без** встроенных заметок/комментариев в строке.
- Колонка «Лишнее?»: `✗`/`дистрактор` → в `distractors`, иначе → в `words`.
- Дистракторов — **от 3 до 5** (НЕ всегда 3 — варьировать число; таблица/модель поддерживают любое количество).

### TextInput → `items[{sentence, contextRu, answer, alternatives}]`, `explanation`
```
**Ex N · TextInput** *(ID: X)*
<инструкция, опц. — в БД не идёт>
1. "<предложение с ___>" (опц. контекст)
   Ответ: **answer**
2. "<ещё предложение ___>"
   Ответ: **—**
*Explanation ...:* ...
```
1–5 пунктов (новые писать по 3–5). `Ответ: **—**` = пустой ответ. Альтернативы: `Ответ: **a** / **b**`.
⚠️ Строго: маркер ответа — **только `Ответ:`** (не «Правильный ответ:», не «Правильные ответы:»).
Контекст — в **обычных** скобках `(...)`, **НЕ** `*(...)*`. Предложение — в обычных кавычках,
**БЕЗ** italic-обёртки `*"..."*`. **Никаких** `Подсказка:`. Стрелка `→` в самом предложении-подсказке
допустима (`"one knife → two ___"`), но ответ — отдельной строкой `Ответ:`, не `→ **answer**`.

### Matching → `taskDescription, pairs[{left, right}], explanation`
```
**Ex N · Matching** *(ID: X)*
Задание: <одна строка>
| Левая | Правая |
| he | он |
*Explanation ...:* ...
```
4–6 пар. Первая строка таблицы (заголовки колонок) пропускается — пользователь их не видит.
⚠️ В таблице — **ПРАВИЛЬНЫЕ пары** (left↔right на одной строке). Перемешивание — на рантайме в UI
(пользователь соединяет ниточками). **НЕ перемешивать пары в MD, НЕ использовать строку `*Answers:*`** —
парсер берёт пары строго по строкам таблицы.

### Categorization — два допустимых строя таблицы (оба парсятся)
- Несколько слов в ячейке через запятую: `| Cat1 | Cat2 |` затем `| a, b, c | d, e |`.
- По элементу на строку: `| Cat1 | Cat2 |` затем построчно `| a | d |` / `| b | e |`.
Заголовок таблицы = названия категорий. Пул слов снизу (`**Слова:**`) — необязателен, в БД не идёт
(пул выводится из элементов). Не использовать формат «| предложение | категория |» по строке.

### ErrorCorrection → `wrongSentence, options[{text,isCorrect}], explanation`
```
**Ex N · ErrorCorrection** *(ID: X)*
В предложении есть ошибка. Выбери правильный вариант:
"<сломанное английское предложение>"
- Wrong variant
- **Correct variant** ✓
- Wrong variant
*Explanation ...:* ...
```
⚠️ В условии — только EN, **без русского перевода**. Нужен русский контекст → это FORWARD_CHOICE.

### ConstructionMeaning → `construction, options[{text,isCorrect}], explanation`
```
**Ex N · ConstructionMeaning** *(ID: X)*
Выбери правильный перевод:
"<English grammar construction>"
- **Правильный перевод** ✓
- Неправильный перевод
- Неправильный перевод
- Неправильный перевод
*Explanation ...:* ...
```
Ровно 4 варианта (русские переводы).

### Transformation → `taskDescription, items[{original, transformed}], explanation`
```
**Ex N · Transformation** *(ID: X)*
Задание: <одна строка>
1. "<Original sentence.>" → **"<Transformed sentence.>"**
2. ...
3. ...
*Explanation ...:* ...
```
Ровно 3 пункта. Разделитель `→`, трансформированное предложение в `**…**`. Предложения в обычных
кавычках, **БЕЗ** italic-обёртки `*"..."*`. Это всегда одна трансформация на 3 примера — формат
«Дано / сделай отрицание и вопрос» НЕ использовать (это не один тип трансформации).

### Categorization → `taskDescription, categories[{title, items[]}], explanation`
```
**Ex N · Categorization** *(ID: X)*
Задание: <одна строка>
| this (рядом) | that (далеко) |
| Книга в руках | Здание вдали |
*Explanation ...:* ...
```
2–3 категории (заголовки колонок = названия категорий), 6–15 элементов суммарно. Пустые ячейки и `—` пропускаются.

### FindTheOdd → `groupDescription, items[{text, isOdd}], explanation`
```
**Ex N · FindTheOdd** *(ID: X)*
<что объединяет три из четырёх — одна строка>:
- here
- there
- where
- **when** ✓
*Explanation ...:* ...
```
Ровно 4 элемента. Лишний помечается **только `✓`** (жирным) — слово «(лишнее)» НЕ писать, галочки достаточно.
⚠️ Элементы — **только сами слова/конструкции**, без аннотаций типа `→ ответ: …`. Пояснения — в `explanation`.

### DialogRestore → `lines[{speaker, text}], options[{text,isCorrect}], explanation`

**ЭТАЛОН** (пропуск = ЦЕЛАЯ реплика, варианты = ЦЕЛЫЕ реплики, не одно слово):
```
**Ex N · DialogRestore** *(ID: X)*
A: "I love this film so much!"
B: ___

- Me also!
- I too love it!
- **Me too!** ✓
*Explanation ...:* ...
```
Строк в диалоге может быть **несколько** (`lines` — массив): например `A:` вопрос → `B: ___` →
`A:` ответ. Пропуск — **ровно одна** реплика целиком (`B: ___` → text:null).

**Жёсткие правила (иначе парсер не возьмёт / выйдет каша):**
- Реплики только `A:` / `B:`. **НЕ** использовать `> —`, `— `, blockquote.
- Пропуск только `___` отдельной репликой. **НЕ** `[???]`, **НЕ** пропуск-слово внутри строки.
- Варианты — **целые реплики**, формат `- Реплика` / `- **Правильная реплика** ✓`. **НЕ** `a)/b)/c)`,
  **НЕ** одно слово (для одного слова — это TextInput/CHOICE, а не DialogRestore).

## ❌ Антипаттерны — частые ошибки оформления (НЕ повторять!)

> Всё это реально вылезло при верификации «Основ» и сломало парсинг/данные. Свериться перед сдачей.

**Общее (любой тип):**
- ❌ нет `*Explanation:*` → ✓ обязателен у КАЖДОГО упражнения.
- ❌ `*Explanation: текст*` (вся строка курсивом) → ✓ `*Explanation:* текст` (курсив только ярлык).
- ❌ `✗` / `a)` `b)` `c)` в тексте опции → ✓ только `- Текст` / `- **Текст** ✓`.

**TableFill:** ❌ 3 колонки с `___` в ответе, ответы в `*Answers:*`, колонка-«правило» → ✓ 2 колонки: подсказка | сам ответ.

**MultipleChoice:** ❌ строка-инструкция в prompt («Переведи на русский:» и т.п.) → ✓ prompt = предложение; русский контекст — строкой `RU: …` (идёт в `contextRu`) или в скобках `(...)`.

**TrueFalse:** ❌ мета-утверждения («"Forty" is correct spelling»), 3 колонки `| # | Утверждение | Верно? |` → ✓ 4 колонки `| # | EN | RU | Верно? |`, живые предложения.

**Matching:** ❌ перемешанные пары + строка `*Answers:*` → ✓ таблица = ПРАВИЛЬНЫЕ пары (left↔right на строке), перемешивает UI.

**Categorization:** ❌ формат `| предложение | категория |` построчно → ✓ заголовок = категории, элементы в их ячейках.

**TextInput:** ❌ `Правильный(е) ответ(ы):`, italic `*"..."*`, контекст `*(...)*`, строка `Подсказка:`, `→ **ответ**` → ✓ `Ответ: **X**`, контекст `(...)`, пропуск `___`.

**Transformation:** ❌ маркеры `[and] "..." + "..."`, italic `*"..."*`, формат «Дано / сделай отрицание и вопрос» → ✓ `1. "orig" → **"transformed"**` ×3, одна трансформация.

**FindTheOdd:** ❌ аннотации `→ ответ: ...` в элементах, слово `(лишнее)` → ✓ элементы = только слова, лишний = `**слово** ✓` (галочки достаточно).

**DialogRestore:** ❌ `> —` / `— ` / `[???]`, пропуск-слово в строке, опции `a)/b)` или из одного слова → ✓ `A:`/`B:`, пропуск = целая реплика `B: ___`, опции = целые реплики.

**WordArrangement:** ❌ голая строка-кавычка вместо `RU:`, `Правильные предложения:` (мн.ч.), встроенные заметки `/.../`, колонка «Перевод» → ✓ `RU: ...`, `Правильное предложение: **...**` (ед.ч.), таблица в 2 колонки `Слово | Лишнее?`.

**Words8r Sync:** ❌ дубль слово+перевод в одной категории → ✓ уникальные (омонимы с разным переводом — ОК).

**Теория:** канон плашки — `**Ловушка:** тело` (callout). Конвертер распознаёт плашку и когда ярлык целиком в болде (`**Ловушка: …**`), и когда ярлык на отдельной строке с блоком-телом ниже — все формы дают callout (см. theory_content_guide §8). `heading` (подзаголовок) = вся строка в болде БЕЗ ключевого слова плашки.

## 1. TableFill

**Суть:** таблица с подсказками → пользователь вписывает ответ в каждую ячейку.

**Формат:**
```
Задание: [одна строка — что заполнять]

| [Подсказка или Подлежащее] | Ответ |
|---------------------------|-------|
| hint1                     | answer1 |
| hint2                     | answer2 |
```

**explanation:** полное правило группой (не каждый ответ по отдельности) + самая частая ошибка.

**Типичные ошибки при написании:**
- Объяснять каждый ответ отдельно — не нужно, объясняй правило
- Таблица длиннее 7 строк — разбить на два упражнения
- ⚠️ Брать те же слова, что в примерах теории карточки — пользователь спишет готовое. Дать ~3 из
  теории + остальные **новые** (из курса, но не из примеров этой карточки); подсказка — в начальной
  форме, ответ пусть выводит сам. Не вставлять `—`/пустые ячейки ради ровного числа.

## 2. MultipleChoice · CHOICE

**Суть:** предложение с пропуском → выбрать из 2–4 вариантов.

**Формат:**
```
"Предложение с ___." (контекст по-русски в скобках если нужен)

- Вариант
- **Правильный вариант** ✓
- Вариант
```

**explanation:** почему правильный — чётко. Почему каждый неправильный — коротко.

**Типичные ошибки при написании:**
- Правильный ответ всегда на второй позиции — чередовать
- Дистракторы нереалистичные — должны быть типичными ошибками, не абсурдом

---

## 3. MultipleChoice · FORWARD_CHOICE (RU → EN)

**Суть:** русский контекст/предложение → выбрать правильный английский вариант.

**Эталон:** Ex 84.

**Формат:**
```
[Ситуация если нужен контекст:]
"Русское предложение."

- English option
- **English correct option** ✓
- English option
```

**Правила:**
- Если прямой перевод фразы — просто русское предложение без "Выбери английский перевод:"
- Если важен контекст (расстояние, ситуация, интонация) — добавить описание ситуации перед предложением
- Варианты отличаются только нужным грамматическим элементом

**explanation:** почему этот вариант подходит для данной ситуации + чем отличаются неправильные.

---

## 4. MultipleChoice · REVERSE_CHOICE (EN → RU)

**Суть:** английское предложение → выбрать правильный русский перевод.

**Формат:**
```
Переведи на русский:
"English sentence."

- Русский вариант
- **Правильный русский вариант** ✓
- Русский вариант
```

**explanation:** разобрать ключевые слова EN → RU, указать чем отличаются варианты.

## 5. TrueFalse

**Суть:** 5 предложений → пользователь отмечает каждое верно/неверно. Число верных и неверных гибкое (минимум 2 ✓ и 2 ✗ (не показывать эту подсказку пользвоателю)).

**Формат (стандартный — с переводом):**
```
| # | EN | RU | Верно? |
|---|----|----|--------|
| 1 | English sentence. | Русский перевод. | ✓ |
| 2 | Wrong sentence. | Перевод. | ✗ |
```

**Формат (ситуационный — без RU, когда смысл даётся ситуацией):**
```
| # | Ситуация | EN | Верно? |
|---|----------|----|--------|
| 1 | Описание ситуации. | English sentence. | ✓ |
```

**Правила:**
- Всегда ровно 5 предложений
- Неверные предложения — конкретная грамматическая ошибка, не просто "другой смысл"

**explanation:** указать только неверные строки и объяснить ошибку в каждой. Верные не пересказывать.

## 6. WordArrangement

**Суть:** перемешанные слова → собрать правильное предложение. Есть дистракторы.

**Формат:**
```
[RU: перевод.] ИЛИ [Ситуация: описание контекста.]

Правильное предложение: **English sentence.**

| Слово | Лишнее? |
|-------|---------|
| Word  | —       |
| KnownWord | —   |
| Distractor | ✗ дистрактор |
```

**Правила:**
- Таблица — 2 колонки `| Слово | Лишнее? |`. Перевод не пишем (чипы его не показывают; long-press переведёт).
- `RU:` — когда задание это перевод. `Ситуация:` — когда нужен контекст.
- Дистракторов — от 3 до 5 (варьировать число, не всегда 3)
- Дистракторы — реалистичные ошибки: другая форма глагола, неверное местоимение, неправильный предлог

**explanation:** объяснять только ошибочные части, не всё предложение. Дистракторы — почему каждый не подходит.

## 7. TextInput

**Суть:** предложения с пропусками → вписать правильный ответ вручную (case-insensitive).

**Формат (стандартный — несколько пунктов):**
```
1. "___ is the capital of France?" (Спрашиваю о городе)
   Ответ: **What**

2. "___ are you late?" (Хочу узнать причину)
   Ответ: **Why**

3. "___ does she live?" (Спрашиваю о месте)
   Ответ: **Where**
```

**Правила:**
- Минимум 2 пункта, обычно 3
- Контекст в скобках — подсказка на русском. Когда проверяем ВЫБОР слова (where/what/предлог) —
  не выдавать перевод самого пропуска. Когда проверяем ФОРМУ уже известного слова (глагол + `-s`) —
  наоборот, дать русский смысл слова `(пьёт)`, чтобы юзер сам вспомнил английское слово и поставил
  форму; НЕ давать английский инфинитив `(глагол to drink)` — это готовый ответ, думать не надо.
- Сокращения (`isn't`/`is not`, `I'll`/`I will` и т.п.) перечислять через `/` НЕ нужно —
  `AnswerNormalizer` раскрывает их в обе стороны автоматически. `Ответ: **a** / **b**` —
  только для реально РАЗНЫХ по смыслу допустимых вариантов.

**explanation:** общее правило для серии + типичные ошибки (регистр, апостроф и т.д.).

## 8. DialogRestore

**Суть:** диалог с пропуском → выбрать правильную реплику.

**Формат:**
```
A: "Реплика или вопрос?"
B: ___

- Wrong option
- **Correct option** ✓
- Wrong option
```

**Правила:**
- Всегда 3 варианта, все на английском
- Неправильные — грамматически неверные формы (isn't/aren't/am not и т.д.), а не просто другой смысл
- Использовать только после изучения вопросов и отрицаний

**explanation:** почему именно эта грамматическая форма правильная, а не просто "так говорят".

## 9. ErrorCorrection

**Суть:** сломанное английское предложение → выбрать правильный вариант.

**Формат:**
```
В предложении есть ошибка. Выбери правильный вариант:

"Wrong English sentence."

- Wrong variant
- **Correct variant** ✓
- Wrong variant
```

**Правила:**
- В условии — только сломанное английское предложение, без русского перевода
- Если нужен русский контекст → использовать FORWARD_CHOICE вместо ErrorCorrection
- Только правильный вариант помечается ✓
- Неправильные варианты — другие частые ошибки на то же правило

**explanation:** назвать конкретную ошибку в исходном предложении + объяснить правило.

## 11. Matching

**Суть:** 4–6 пар → соединить линиями.

**Формат:**
```
Задание: соедини [что] с [чем].

| Левая колонка | Правая колонка |
|---------------|----------------|
| item1         | match1         |
| item2         | match2         |
| item3         | match3         |
| item4         | match4         |
```

**Правила:**
- 4–6 пар. 4 — стандарт; до 6 когда нужно покрыть весь логический список (например все вопросительные слова)
- Без ✓ маркеров — пользователь соединяет интерактивно
- Названия колонок — произвольные под контент, пользователь их не видит

**explanation:** краткое правило по каждой паре.

## 12. Categorization

**Суть:** слова/ситуации → перетащить в правильные колонки-категории.

**Формат:**
```
Задание: перетащи [что] в нужную колонку.

| Категория 1 | Категория 2 |
|-------------|-------------|
| item1       | item2       |
| item3       | item4       |
```

**Правила:**
- 2–3 категории
- 3–5 элементов в каждой (итого 6–15 элементов)
- Использовать только там где это логично: предлоги in/on/at, маркеры времени, типы слов
- ⚠️ Не брать те же слова, что в примерах теории карточки (юзер спишет). ~3 из теории + остальные
  **новые** (из курса, не из примеров карточки). Слово давать в **начальной форме**, чтобы он сам
  решил окончание/столбик, а не выдавать готовую форму. Не вставлять `—`/пустые ячейки ради числа.

**explanation:** правило для каждой категории одной строкой.

## 13. Transformation

**Суть:** дано предложение → трансформировать по правилу.

**Формат:**
```
Задание: [описание трансформации — одна строка]

1. "Original sentence." → **"Transformed sentence."**
2. "Original sentence." → **"Transformed sentence."**
3. "Original sentence." → **"Transformed sentence."**
```

**Правила:**
- Всегда 3 пункта
- Одна трансформация на всё упражнение — одно правило, три разных примера
- Тип трансформации может быть любым: this→these, "of X"→"X's", утверждение→вопрос и т.д.

**explanation:** назвать правило трансформации + что чаще всего упускают (артикль, порядок слов, форму глагола).

## 14. FindTheOdd

**Суть:** 4 слова/конструкции — найти лишнее.

**Формат:**
```
[Что объединяет три из четырёх — одним предложением]:

- item1
- item2
- item3
- **item4 (лишнее)** ✓
```

**Правила:**
- Всегда 4 элемента, один правильный ответ
- Объяснение ЧТО объединяет три — обязательно в условии задания
- Использовать только там где "лишнее" логически очевидно по правилу, не по ощущению

**explanation:** назвать принцип объединения трёх + почему четвёртое не подходит.

## 15. AI Exercise

**Суть:** задание генерируется AI в реальном времени по шаблону промта. Пользователь отвечает в свободное поле или заполняет пропуски прямо в тексте.

**Формат:**
```
**Title:** "Короткое название задания"
**Input Mode:** FREE_WRITE / FILL_BLANKS
**Words Source:** NONE / GENERAL / INFORMAL_ENGLISH / VERB_FORMS
**AI Config Profile:** EXERCISE_LIGHT / EVALUATION_ONLY / EXERCISE_HEAVY_50..500
**User Instruction:** "Одна строка — что делать пользователю. Показывается до нажатия [Начать задание]."
**Prompt Template:** "Полная инструкция для AI. Что генерировать, как проверять ответ, как объяснять ошибку. Последняя строка: Пример вывода AI: 'конкретный текст который AI выдаст пользователю'."
```

**Правила по полям:**

| Поле | Правило |
|------|---------|
| Title | Глагол + объект: "Вставь предлог", "Переведи предложение", "Сделай отрицание" |
| Input Mode | FILL_BLANKS — если AI присылает текст с пропусками `[___]`. FREE_WRITE — всё остальное |
| Words Source | NONE для большинства упражнений предтемы. GENERAL когда нужны слова из словаря пользователя |
| AI Config Profile | EXERCISE_LIGHT — стандарт. EXERCISE_HEAVY если ответ AI > 100 токенов |
| User Instruction | Без технических деталей — только что делать. Не упоминать AI, не объяснять механику |
| Prompt Template | Обязательно заканчивается строкой `Пример вывода AI: '...'` с конкретным текстом |

**Правила Prompt Template:**
- Написать ЧТО генерировать (тип задания, язык, длину)
- Написать КАК проверять (что считать правильным, принимать ли сокращения)
- Написать КАК объяснять ошибку (по-русски, конкретно, без воды)
- `Пример вывода AI:` — обязателен. Без него нельзя проверить корректность задания

**Типичные ошибки при написании:**
- Нет `Пример вывода AI:` — нельзя проверить что AI выдаст
- User Instruction слишком техническая ("AI даст FILL_BLANKS...") — пользователь это не должен видеть
- Prompt Template не указывает язык объяснения ошибки — AI может ответить по-английски
