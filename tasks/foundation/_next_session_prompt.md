### 4.0 Сквозные правила всей группы (F3 и F4) — решены пользователем

- **Вердикт multi-answer — all-or-nothing на уровне экрана** (схему `user.db` НЕ трогаем,
  `UserExerciseResult.correctFirstTry` — как есть):
  - «Проверить» → проверяются все ячейки/слоты разом.
  - Все верны с первой попытки → `correctFirstTry = true`.
  - **1-я ошибка → НИЧЕГО не подсвечиваем**, только сообщение «Неправильно, попробуйте ещё раз»
    (снекбар как сейчас). Пользователь ищет ошибку сам, ответ не стираем. Это анти-спойлер.
  - **2-я ошибка → reveal:** подсвечиваем что верно (зелёным) / что неверно (красным) +
    дозаполнение правильными + общий `ExerciseExplanation`.
  - ⚠️ Для **CATEGORIZATION с >2 колонками** «подсветить неверное красным» недостаточно (неясно, в
    какую из ≥2 других колонок). Решение (предложено, подтвердить при реализации): на финальном reveal
    **автоматически перенести каждый неверно разложенный элемент в его правильную колонку** с
    анимацией (неверно стоявшие — красная рамка на миг, верные — зелёная), так корректный ответ виден
    при любом числе колонок. Для 2 колонок достаточно красной подсветки неверных (правильная очевидна).
- **`AnswerNormalizer` (`domain/usecase/AnswerNormalizer.kt`) расширить:** игнорировать при сравнении
  **любые знаки препинания** (точки, запятые, ВСЕ punctuation) и лишние пробелы. Чел поставил лишнюю
  запятую/точку/двойной пробел — засчитываем. Делать в ТОМ ЖЕ классе (или вызываемом им) — чтобы
  работало везде, где уже применяется `AnswerNormalizer` (TextInput + TABLE_FILL + TRANSFORMATION +
  WORD_ARRANGEMENT). `is not == isn't` уже покрыто (CONTRACTIONS), проверено.

### 4.1 Типы F3

- **TABLE_FILL** — таблица `rows[{hint, answer}]`, вписать ответ в каждую строку. Текстовый ввод —
  `ExerciseAnswer.TextAnswers` (строка на ячейку), проверка `AnswerNormalizer`. Рендер —
  **переиспользовать механизм «плавающего поля ввода»** из TextInput (поле `BlankBar`, подстраивается
  под длину), строки `подсказка | поле`. Не плодить (Правило №0).
- **TRANSFORMATION** — `taskDescription` + ровно 3 пары `items[{original, transformed}]`. Ввод
  трансформированного предложения для каждого из 3 — `TextAnswers` ×3, `AnswerNormalizer`. Подача:
  `original → поле ввода`. По сути TextInput на 3 поля.
- **WORD_ARRANGEMENT** — `situationRu` + `correctSentence` + `words[]` + `distractors[]`. **Duolingo-style
  drag-сборка** (НЕ просто тап): чипы в банке + зона сборки; слово можно **перетащить и вставить между
  другими словами**, при перетаскивании остальные чипы **разъезжаются**, открывая «дырку»-плейсхолдер
  под пальцем (см. скрины `tasks/img.png`, `tasks/img_1.png`). Тап = быстрое добавление/возврат, но
  ОБЯЗАТЕЛЬНО и drag-reorder. **Нужен НОВЫЙ `ExerciseAnswer`** (упорядоченный список токенов) + ветка
  evaluator (собранное vs `correctSentence` через `AnswerNormalizer`) + рендерер с чипами.
  ⚠️ Официального «reorderable FlowRow» в Compose НЕТ → drag с рефлоу — ручная реализация на
  официальных кирпичах (`detectDragGestures`, анимированные смещения/`animateItem`). Это легитимный
  случай «нет официального API» (протокол костылей), пользователь явно просит это поведение.
  Чипы — контентные EN → `TranslatableText` (long-press-перевод пока заглушка, обёртка с 1-го дня).
- Маппинг типов — `ExerciseRepositoryImpl`; доменные варианты — `Exercise`. DAO-геттеры уже есть.
- Контент во всех 5 сидах (не только basics): WORD_ARRANGEMENT 50, TRANSFORMATION 14, TABLE_FILL 9.
- **DoD F3:** типы проходятся в сессии вживую; плашка `Unsupported` для них больше не появляется.
- **decision_log** (каждое 🟡) + **notes_for_fable**. В конце — roadmap (F3 ✅), этот файл под **F4**.

### 4.2 F4 — уже согласованные механики (записать сюда, реализовать после F3)

- **TRUE_FALSE** — **НЕ тоггл ✓/✗**, а **multi-select «отметь верные»**: тап по предложению → зелёное
  (как выбор варианта). Условие «Выберите верные варианты». Ложится на ту же механику выбора, что и
  SingleSelect, но **multi-correct multi-select** (выбрать ВСЕ `isTrue`). 2-я ошибка → верные зелёным,
  неверно выбранные/пропущенные красным. Данные `statements[{en,ru,isTrue}]` ×5.
- **MATCHING** — **БЕЗ ниточек.** Две колонки друг напротив друга, **левая закреплена**, **правую
  переставляют вертикальным drag-reorder** (та же механика, что WORD_ARRANGEMENT, но по вертикали:
  фрейм под пальцем, остальные разъезжаются). Вердикт: правый элемент напротив верного левого.
- **CATEGORIZATION** — **drag из пула в колонки и обратно** (туда-сюда, красиво — не тап). Чтобы при
  броске не было скачка размера — **элементы в пуле сразу рендерить в том размере, в котором они
  встанут в колонку** (пресайз под ширину фрейма колонки).
- ⚠️ **Габариты (CATEGORIZATION/MATCHING/TABLE_FILL):** таблица + пул обязаны влезать на ОДИН экран
  телефона — правило записано в `CLAUDE.md` и `exercise_templates.md` (для автора контента).
