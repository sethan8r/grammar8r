### 2026-06-14 · Объём Шага B: словарь Words8r отложен, irregular_verbs включён
- **Контекст:** какие таблицы content.db заводить в схеме Room на Шаге B.
- **Варианты:** (а) всё из db_schema, включая шиппованный словарь Words8r (17170); (б) только то,
  что нужно для обкатки теории/упражнений + хорошо специфицированные таблицы курса.
- **Выбор:** (б). Включены теория (4), упражнения (12 типов + index + ai), слова курса
  (`course_word_groups/categories/words`, `irregular_verbs`), весь user.db (10). Словарь Words8r —
  НЕ заводим.
- **Почему:** kickoff_context.md §6.2 прямо относит словарь Words8r и его перенос к Фазе 2
  (вкладка «Слова»); roadmap Шага B говорит «слова курса», словарь там не упомянут. db_schema
  описывает словарь как перенос из `tasks/words8r.db`, не из MD→JSON конвейера. Для текущей цели
  (читалка + движок на basics.json) он не нужен, схема его частей по сути TBD. `irregular_verbs`
  включён, хотя в basics.json его нет: схема готова, на него уже завязан `UserWordProgress(IRREGULAR_VERBS)`.
- **Уверенность:** высокая.
- **Обратимость:** легко — добавить Entity словаря + bump версии content.db в Фазе 2.

### 2026-06-14 · JSON-поля хранятся как String, разбор — в domain-маппере (не Room TypeConverter)
- **Контекст:** `GrammarCard.theory` (массив блоков), `examples`, `clarificationOptions`, а также
  `options/items/rows/pairs/words/...` в таблицах упражнений и `topicsVisited` в DailyStats.
- **Варианты:** (а) Room `@TypeConverter` String↔типизированная модель прямо в Entity;
  (б) Entity держит сырой `String` (колонка TEXT), типизированный разбор делает domain-маппер
  при чтении Entity→domain-модель.
- **Выбор:** (б). TypeConverter оставлен ТОЛЬКО для enum↔String.
- **Почему:** колонка в обоих вариантах TEXT (на identity hash content.db не влияет), но (б)
  не пускает kotlinx.serialization в data-слой и держит границу data→domain чистой; разбор
  блоков — это уже задача читалки (Шаг E), а не схемы. Entity остаётся «глупым» отражением строки.
- **Уверенность:** средняя — Fable пусть подтвердит, что разбор JSON в маппере (а не в конвертере)
  ему ок с точки зрения границ слоёв.
- **Обратимость:** средняя — перенос разбора в TypeConverter не трогает схему БД (тип колонки тот же),
  меняет только где живёт сериализация.

### 2026-06-14 · Между БД нет FK; внутри content.db FK тоже не ставим — только индексы
- **Контекст:** связи `categoryId`/`topicId`/`microtopicId`/`cardId` и т.п.
- **Варианты:** (а) `@ForeignKey` внутри content.db (между БД нельзя — это правило db_schema);
  (б) только `@Index` на FK-колонках, без `@ForeignKey`.
- **Выбор:** (б) везде.
- **Почему:** content.db сидируется из JSON скриптом (Шаг C) — `@ForeignKey` потребовал бы строгого
  порядка вставки и падал бы на любой осиротевшей ссылке, что противоречит правилу «осиротевшее
  игнорируется». Целостность контента гарантируется на этапе авторства (id_report.py), а не БД.
  Индексы под выборки оставлены.
- **Уверенность:** высокая.
- **Обратимость:** средняя — добавить `@ForeignKey` = bump версии (меняется identity), но для
  read-only content.db это дёшево (destructive fallback).

- **Уверенность:** высокая.

- **Заметка:** `AiExerciseWordsSource.displayName` временно живёт как доменный атрибут enum'а;
  при появлении экрана блокировки упражнения уедет в strings.xml.

### 2026-06-14 · createFromAsset объявлен сразу, открытие ленивое (файла ещё нет)
- **Контекст:** content.db файл появится только в Шаге C (сидинг), а провайдер пишем сейчас.
- **Выбор:** провайдер `ContentDatabase` уже зовёт `.createFromAsset("content.db")`. На Шаге B к DAO

- **Почему:** лучше не забыть потом; настоящая проверка открытия — DoD Шага C.
- **Уверенность:** высокая. **Обратимость:** тривиальная.

### 2026-06-14 · AiRequestCounter — провизорная минимальная схема (date, count)
- **Контекст:** db_schema держит `AiRequestCounter` в «незафиксированных».
- **Выбор:** завёл `AiRequestCounter(date: String PK, count: Int)` по образцу `DailyStats.date` (MSK).
- **Почему:** не оставлять дырку в user.db; механика «сброс 00:00 MSK + инкремент счётчика» из
  subscription.md ложится на дневной ключ. Финал — Шаг D2 (EntitlementsProvider) / Фаза 4.
- **Уверенность:** низкая — Fable/сервер пусть подтвердят, не нужен ли учёт по типам запросов
  или серверный источник правды вместо локального счётчика.
- **Обратимость:** высокая (user.db, но через ЧЕСТНУЮ миграцию — destructive здесь запрещён).
