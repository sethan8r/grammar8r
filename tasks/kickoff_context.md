## 1. Что произошло и что решено

1. Проведён **полный аудит кода Words8r** (`E:\AndroidProjects\SethanWords`) — найдены

3. **Решение пользователя:** Words8r не копируется, а **переписывается с нуля внутри
   Grammar8r**. Одно приложение, одна БД (легаси-план про два приложения — отменён).
   Функциональность блока слов сохраняется 1:1, архитектура — новая.
4. **Планка качества** (записана в начале words8r_lessons.md), цитата пользователя:
   > «Я хочу сделать новое приложение максимально качественным, как будто над ним большая
   > опытная команда сеньоров работала. Ибо приложение сложное, контента и функциональности
   > много и в этом всем можно увязнуть спокойно.»
   Ориентир — уровень Duolingo и других крупных продакшен-приложений. Grammar8r будет
   монетизироваться (подписки), это продакшен-продукт.

## 2. Порядок работ — ВАЖНО, здесь было недопонимание

Пользователь предполагал начать с переписывания Words8r («это база, которую надо просто
переделать»). **Это не так — зафиксирован обратный порядок**, согласованный с
`phases/development_plan.md`:

```
Шаг 1. Фундамент приложения        ← Hilt, Room, слои, сидинг, серверные заглушки
Шаг 2. Теория (Фаза 1)             ← читалка контента на УЖЕ готовых темах
        └─ цель: обкатать и зафиксировать формат контента, пока тем мало
Шаг 3. Хардкодные упражнения       ← движок + 14 типов, по очереди
Шаг 4. Words8r внутри Grammar8r    ← Фаза 2: блок слов с нуля, функционал 1:1
Шаг 5. AI + Практика (Фаза 3), Сервер + Монетизация (Фаза 4)
```

**Почему теория раньше Words8r:** главный риск проекта — формат контента теории
(JSON-структура карточек/блоков из `tools/md_to_json.py`). Он ещё ни разу не проверен
реальным рендерером. Когда читалка начнёт его рендерить, почти наверняка потребуются
правки формата (недостающие поля, неудобные типы блоков, theorySummary для AI и т.п.).
Сейчас готово всего 3–4 темы — править дёшево. Если сначала месяц делать Words8r,
пользователь за это время напишет ещё тем, и каждая правка формата будет дорожать.
Блок слов, наоборот, самодостаточен: его поведение зафиксировано в `words8r_plan.md`
и от формата теории не зависит — он спокойно ждёт своей фазы.

**Установка для пользователя (он согласился):** НЕ дописывать новые темы теории, пока
формат не обкатан читалкой и не объявлен стабильным. После стабилизации — контент пишется
параллельно с разработкой, и новые темы «просто добавляются в БД и всё работает»
(приложение data-driven, о конкретных темах не знает).

## 3. Серверные заглушки — требование пользователя

Цитата: «надо оставлять заглушки для сервера, допустим, для JWT, для подписок и все такое».

Реализация — строго по правилам words8r_lessons.md (раздел 6.2, никаких
«TODO раскомментировать перед релизом»):
- Интерфейсы в domain: `AuthRepository` (JWT/OAuth), `EntitlementsProvider` (тир подписки,
  AI-лимиты), `AiExerciseRepository`, синк прогресса.
- Фейковые реализации (`Fake*`/`Local*`) биндятся через Hilt-модули. Когда появится
  сервер (Spring Boot на Java, Фаза 4) — меняется только биндинг, ни строчки в фичах.
- Поведение dev/prod — через BuildConfig-поля, не через комментарии в коде.

### 3.1. Модуль `grammar-shared` — контракт клиент↔сервер

В проекте три Gradle-модуля: `grammar-app` (приложение), `grammar-server` (Spring Boot на Java, Фаза 4)
и `grammar-shared`. Сейчас shared — пустой плейсхолдер (`Models.kt` с пустым классом),
но удалять его НЕ надо — это стандартный паттерн для монорепо «клиент + сервер».

**Зачем:** модели запросов/ответов API пишутся в shared ОДИН раз с `@Serializable`;
и приложение, и сервер подключают модуль через `implementation(project(":grammar-shared"))`.
При сборке классы shared упаковываются в оба артефакта (APK и jar). Контракт не может
разъехаться: переименовал поле — не компилируются обе стороны сразу, ошибка видна на
сборке, а не как битый JSON в проде.

**Роль по фазам:**
- **Фаза 1 (фундамент):** DTO для серверных заглушек (`AuthRepository`,
  `EntitlementsProvider`, `AiExerciseRepository`, синк прогресса) создаются сразу в shared,
  а не внутри приложения. Пустой `Models.kt` при этом удаляется.
- **Фаза 4 (сервер):** `grammar-server` реализует эндпоинты по уже готовым DTO из shared —
  ничего не переносится и не дублируется.

**Что лежит:** только `@Serializable` DTO API + enum-ы контракта (тир подписки,
`AiExerciseInputMode`, коды ошибок). **Что запрещено:** Room-сущности, UI/доменные модели,
бизнес-логика, Android-зависимости — модуль чистый Kotlin/JVM. Подробное правило — в
CLAUDE.md проекта, раздел «Модули проекта и роль grammar-shared».

## 6.2. Закладки в скелет из планов фич (12.06.2026)

Дешёвые решения первого дня, чтобы будущие фазы ложились без переделок:

1. **`EntitlementsProvider` — полный интерфейс сразу:** тир, AI-запросов/день,
   микротем/день (Free), заморозки стрика. ⚠️ Лимита «слов в промте» НЕТ — выборка слов
   для AI фиксирована для всех тиров (отказ 12.06.2026, см. subscription.md).
2. **Состояния микротемы в UI-модели теории — enum, не Boolean:** заблокирована дневным
   лимитом Free (Фаза 4) / доступна / пройдена / есть неоткрытые слова → иконка Download.
3. **«Микротема завершена» — единый use case / поток событий в domain.** Подписчики
   добавляются по фазам: BottomSheet открытия слов, стрик/статистика, серверный синк,
   диалог повторного прохождения. Логику завершения НЕ размазывать по ViewModel.
4. **Единая точка записи прогресса/активности** — один репозиторий/use case, через который
   идут ВСЕ записи (карточка пройдена, упражнение отвечено, AI выполнен). Сейчас пишет
   `DailyStats` (сокращённая схема — см. features.md «Статистика»), потом туда же
   подключатся стрик и синк. Разрозненные `dao.update()` из ViewModel — запрещены.
5. **Каркас экрана упражнения** (общий scaffold всех 14 типов) сразу содержит: ID упражнения
   мелким курсивом в углу (`MultipleChoice · CHOICE 71` — для баг-репортов), слот «объяснение
   при неверном ответе», прогресс «X из N», кнопку `?` (theorySummary).
6. **Карточка теории — слоты под Фазу 3:** внизу зарезервированы места под AI-блок
   («Умное задание») и кнопку «Не совсем понял» (пока задизейбленные заглушки).

**Плюс в объём первой сессии входит открытие слов** (для обкатки полного флоу микротемы):
таблицы слов курса в content.db, флаги `isView`/`isHiding` в user.db, BottomSheet открытия
слов после микротемы, иконка Download на строке микротемы (если шторку закрыли без
подтверждения — слова можно открыть позже). Само изучение слов (SRS, вкладка «Слова») —
остаётся в Фазе 2.

**Флоу карточки (зафиксировано 12.06.2026):** детально — `phases/phase1/phase1_theory.md`
→ «Структура карточки». Коротко: первый проход — внизу теории одна кнопка «УПРАЖНЕНИЯ»;
«Далее» в упражнениях открывается только после ответа; карточка пройдена → при повторном
входе внизу теории две кнопки: «УПРАЖНЕНИЯ» и «УМНОЕ ЗАДАНИЕ». Повторное прохождение —
анти-чит (см. CLAUDE.md «Повторное прохождение»).

- Лог изменений — в `updates/pending.md` понятным пользователю языком.
