# Grammar8r — Функциональность приложения

> Что умеет приложение. Используется для презентации, App Store описания, и как быстрый справочник по фичам.

---

## Теория

- Грамматика разбита на темы (Present Simple, Past Simple и т.д.) и предтему "Основы"
- Каждая тема разбита на микротемы, каждая микротема — на карточки (одно правило = одна карточка)
- Карточки листаются вверх/вниз
- Прогресс-бар по карточкам внутри микротемы, прогресс по темам на главном экране
- Быстрая навигация по всем темам через BottomSheet-оглавление
- Кнопка "Продолжить" для незавершённых тем
- После завершения микротемы — предложение добавить изученные слова в Words8r
- При первом входе в любую тему после "Основ" — одноразовое предупреждение: проверяем сколько слов из "Grammar Basics" ещё не выучено (qRep = 0), предлагаем выучить сначала. Пользователь может проигнорировать — тогда диалог больше не появляется
- **Поиск** — лупа справа от заголовка вкладки раскрывает строку ввода на его месте, дерево тем сменяется выдачей. Выдача сгруппирована по темам: шапка-тема (тап → экран темы), под ней только те микротемы, которые уточняют запрос (тап → микротема); запрос про тему целиком отвечается одной шапкой. Ищет по названиям тем, микротем и по скрытым тегам (`searchKeywords`), названия карточек — скрытый сигнал релевантности, в выдаче не показываются. Прощает падеж, число, опечатку в букву и написание сокращений (`didn't` = `did not`); механика — `search_feature_brief.md` §11
- **Повторное прохождение** — при входе в пройденную микротему предлагается сбросить хардкодные задания (прогресс темы и AI-статистика не затрагиваются)
- **Карточки-мосты в Практику** — на стыках курса теория сама отправляет пользователя во вкладку «Практика»: закрывающая карточка раздела «Future» (первый круг времён пройден) предлагает отметить все выученные времена и гонять смешанные сессии, чтобы научиться различать времена, а не применять то, которое заранее названо в теме

## Упражнения (хардкодные, бесплатно)

14 типов упражнений — без AI, без лимитов:

| Тип | Описание |
|-----|----------|
| Расстановка слов | Перемешанные слова → собрать предложение |
| Выбор варианта | Пропуск в предложении → выбрать из 2–4 вариантов |
| Выбор EN по RU | RU предложение → выбрать правильный EN вариант |
| Выбор RU по EN | EN предложение → выбрать правильный RU смысл |
| Ввод текста | Пропуск → вписать слово/форму вручную |
| Сопоставление | 4 RU + 4 EN → соединить пары линиями |
| Верно/Неверно | 5 предложений одновременно — отметить какие верны, какие нет |
| Исправь ошибку | Предложение с ошибкой → выбрать правильный вариант |
| Трансформация | Утверждение → сделай отрицание и вопрос |
| Категоризация | Слова перетаскиваешь в колонки-категории |
| Заполни таблицу | Таблица с пропусками (to be, have/has, формы глаголов) |
| Найди лишнее | 4 слова — одно не подходит по правилу |
| Значение конструкции | Грамматическая конструкция → выбрать правильный смысл |
| Восстанови диалог | Диалог с пропуском → выбрать правильную реплику |

При неверном ответе — объяснение почему именно так.

- **ID упражнения** — в углу каждого хардкодного упражнения мелким курсивом: тип и числовой ID (`MultipleChoice · CHOICE 71`). Нужно для баг-репортов: пользователь/тестировщик скидывает скрин — разработчик сразу знает конкретное упражнение в БД.

## Умная практика (AI-упражнения)

- В конце каждой карточки — AI-упражнение по правилу карточки
- Бесплатно: 3 запроса в день. С подпиской — по лимиту тира
- Кнопка **[Начать задание]** — AI-запрос уходит только по явному нажатию (токены не тратятся пока пользователь не готов)
- Текст задания от AI появляется с анимацией "быстрой печати"
- Два режима ввода ответа (`AiExerciseInputMode`):
  - `FREE_WRITE` — пользователь пишет свой ответ в поле снизу
  - `FILL_BLANKS` — AI присылает текст с пропусками `[___]`, клиент рендерит их как встроенные поля ввода прямо в тексте
- После выполнения — фидбек с объяснением ошибок по-русски; для открытых упражнений — score 0–100
- Кнопка "Ещё задание" после каждого выполненного
- `?` в TopBar — показывает `theorySummary` карточки прямо в AlertDialog (не нужно уходить в теорию)
- `❤️` в TopBar — добавить/убрать упражнение из избранного
- **Guard-диалог:** если задание начато но не отправлено, попытка уйти вызывает AlertDialog подтверждения
- **ID упражнения** — мелким курсивом строковый ID AI-упражнения (`auxiliary_card100_ex1`). Та же цель: пользователь скидывает скрин с ID — разработчик сразу находит задание в промт-конфиге.

## AI-уточнение ("Не совсем понял")

- В конце каждой теоретической карточки — кнопка "Не совсем понял"
- Быстрые варианты уточнения (pre-defined) + поле свободного вопроса
- AI объясняет то же правило другими словами и с другим примером
- Не повторяет то, что уже было написано в карточке
- Считается как AI-запрос из дневного лимита

## Практика (отдельная вкладка)

### Избранные упражнения ❤️
- Иконка ❤️ в правом верхнем углу экрана вкладки Практика
- Нажатие → список всех упражнений добавленных в избранное
- Каждое избранное упражнение: название + микротема → нажатие запускает AI-экран
- Добавлять в избранное можно из любого AI-упражнения (кнопка ❤️ в TopBar)

### Случайная практика
- Карточный интерфейс (стопка): на каждой карточке — AI-упражнение из пройденных микротем
- Свайп влево/вправо = пропустить (AI-запрос не отправляется)
- Нажал [Начать задание] — запрос уходит, начинается упражнение
- ❤️ и `?` работают так же как на любом AI-экране
- Guard-диалог если начал задание и пытаешься смахнуть карточку

### Упражнения из теории
- Дерево тем → микротем → карточек, у каждой карточки — её AI-упражнение
- Запускаешь конкретное AI-упражнение без навигации через теорию
- Поиск по названиям тем, микротем и названиям AI-упражнений

### Перевод по пройденным темам
- AI генерирует RU предложения на основе пройденных тем + слов пользователя из Words8r
- Два режима: расстановка слов (с ловушками) или ввод с клавиатуры
- Выбор какие слова включать: новые (qRep 1–8) или хорошо изученные (qRep 9+)
- Требует минимум 50 слов в Words8r

### Перевод рассказа
- AI генерирует английский рассказ из слов пользователя
- Незнакомые слова визуально выделены
- Перевод предложение за предложением с фидбеком
- 4 режима просмотра финала

### Найди все ошибки
- Абзац с 3–5 грамматическими ошибками на пройденные правила
- Тапаешь на неправильные слова → объяснение каждой ошибки

### До/После (проверь свой текст)
- Вводишь любой английский текст
- AI исправляет все ошибки разом с объяснением каждой по-русски

### Заполни форму глагола
- AI генерирует упражнения из глаголов категории "Verb Forms" в Words8r (только те что пользователь уже учит)
- Требует: глаголы с V1/V2/V3 слиты в Words8r после темы «Глаголы V1/V2/V3»

## Онбординг — обучающая микротема «Обучение»

> Реализуется В КОНЦЕ разработки, когда UI устоялся (иначе тур будет описывать то, что ещё
> переедет). Зафиксировано 15.06.2026.

Самая первая «микротема» в списке (до «Основ»), но это **не theory-контент из `content.db`** —
она рендерится силами кода, а её текст живёт в интерфейсных строках (`strings.xml`), потому что
объясняет само приложение, а не английский. Внутри — карточки-тур по всем ключевым механикам:

- что значит зелёный цвет ID, на какие сегменты сверху микротемы можно нажимать
- почему нельзя перепрыгивать и что учить надо **последовательно**
- что происходит после закрытия карточки, когда карточка засчитывается как пройденная
- где искать AI-задания после карточки (вкладка «Практика» либо внизу самой карточки → «к умному заданию»)
- кнопка сброса заданий на пройденной карточке: пройти заново можно, **но старая статистика остаётся** (анти-чит)
- что такое умное задание, что оно иногда подтягивает слова, что делает кнопка «Не совсем понял»
- что такое лимиты, что некоторые умные задания стоят не 1, а несколько поинтов (всегда подписано сколько)
- что слова открываются в словаре после микротемы и почему важно их учить перед переходом дальше
- что в умных заданиях тоже объясняется и закрепляется теория (важно)
- как сообщить о баге: указать ID карточки/задания, куда писать — раздел «Поддержка»
- разные кнопки «учить слова» и «учить слова курса»; у режимов Maze/Wordly свои экраны с инфой
- **последняя карточка:** инфу про подписки и лимиты смотреть в «Профиль» (вкладка «Меню»)

После прохождения тур исчезает из списка. Вернуть его можно кнопкой **«Вернуть обучение»** в
`Меню → О приложении`. Флаг «тур пройден» — в DataStore (настройка поведения, не прогресс).

## Перевод слов по тапу / зажатию — глобальная функция

**Работает на любом английском слове в любом месте приложения** — в теории, упражнениях, AI-практике, схемах, уточнениях. Без исключений.

- Зажать любое английское слово → речевой пузырь (как в комиксах) с переводом и транскрипцией
- Primary: LingvoLive (ABBYY), fallback: Yandex Dictionary
- Самые ходовые переводы идут первыми
- Кнопка "В мои слова" → экран с галочками: выбираешь какие переводы добавить → слово с выбранными переводами + транскрипция летит в Words8r в категорию **"МОИ СЛОВА"**
- Кэш: повторное зажатие того же слова — мгновенно, без запроса к API
- Дубли пропускаются молча

## Разговорный английский

- Отдельная тема, после всех времён
- 5 микротем: gonna/wanna/gotta, coulda/woulda/shoulda, dunno/lemme/gimme, whatcha/whaddya, + современный слэнг (shawty, finesse, slay, lit, vibe — с объяснением происхождения)
- Хардкодные упражнения: формальное → разговорное, разговорное → формальное, Matching, WordArrangement
- AI-практика после каждой карточки: AI даёт контекст, пользователь вставляет разговорную форму
- AI-практика во вкладке "Практика": два режима (Формальное→Разговорное и обратно)
- После каждой микротемы — предложение слить слова в Words8r (категория "Informal English")

## Словарная база (бывший Words8r)

> ⚠️ Words8r переписывается внутри Grammar8r — одно приложение, одна БД. Никакого ContentProvider, никакой межпроцессной коммуникации.

- **Открытие слов после каждой микротемы** у которой есть словарная база:
  - В конце микротемы — BottomSheet "Открыть слова"
  - Слова с галочками (все предвыбраны): ✅ оставил → isView = true; ☐ снял → isView = true + isHiding = true
  - Если закрыл без подтверждения — иконка Download на строке микротемы, можно открыть позже
- Категории: "Grammar Basics" (предтема), "Informal English" (разговорный), остальные определяются при написании контента
- Перевод слов по тапу: LingvoLive (primary) + Yandex Dictionary (fallback) → кэш в Room → кнопка "В мои слова" → isView = true, категория "Мои слова"
- Переход на вкладку "Слова" для изучения форм неправильных глаголов
- **Двухэтапное открытие колоды неправильных глаголов** (🔧 не забыть при разработке):
  - Основная колода (id 1–118) открывается разом в микротеме «Неправильные глаголы» — это то,
    что реально встречается в живой речи, книгах и сериалах
  - Хвост колоды (id 119–198 — редкое, книжное, приставочные производные) открывается ПОЗЖЕ,
    по завершении Card 483 («Second Circle · Второй круг времён пройден»): там юзеру текстом
    обещано, что основная колода закрыта, а остальные глаголы — необязательный добор
    «по желанию, в своём темпе». До Card 483 они не показываются вообще; после — открыты,
    но вне приоритета показа и вне обязательного прогресса/статистики курса
  - Детали: `db_schema.md` → `IrregularVerb.microtopicId`, `words/V1V2V3/irregular_verbs_draft.md`

## Уведомления

- **Push-уведомления** (FCM) — системные уведомления в шторке: технические работы, напоминания о стрике, milestone-подарки. Работают даже когда приложение закрыто.
- **Modal-баннеры** — при открытии приложения, если есть активное сообщение от разработчика. Персональные (от администратора конкретному пользователю) — без срока, показываются до прочтения. Общие — TTL 24 часа.

### Механика доставки (зафиксировано 05.09.2026)

Оба канала «от нас», но технически это **два разных механизма**:

| | Push | Modal-баннер / Новости |
|---|---|---|
| Приложение закрыто | да, в этом весь смысл | нет, только при открытии |
| Как доставляется | наш сервер → **FCM** → устройство | **клиент сам спрашивает** сервер при старте |
| Третьи стороны | Google (FCM) | никого, только наш сервер |
| Гарантия доставки | **нет** | есть: открыл приложение — увидел |

**Пуш своими силами сделать нельзя:** Android гасит фоновые соединения (Doze), собственный
постоянный сокет либо прибьёт система, либо он высадит батарею. Привилегированный всегда-живой
канал есть только у сервисов доставки — поэтому FCM здесь единственный вменяемый путь.

**Баннеры, наоборот, полностью наши** — их не нужно «доставлять»: приложение и так открывается
и само спрашивает сервер, есть ли что показать. Никакой зависимости от Google.

⭐ **Пуш — это будильник, а не содержимое.** Он несёт короткий текст и максимум id; правда всегда
тянется с нашего сервера при открытии. Доставка пуша ненадёжна по своей природе, поэтому ничто
не должно от неё зависеть — непришедший пуш не теряет ничего, человек откроет приложение и всё
получит.

Охват: **только FCM**, устройства без сервисов Google вне охвата осознанно. Детали, требования
к панели и запрос разрешения на Android 13+ — `phases/phase4/phase4_server.md` →
«Push-уведомления: как доставляются».

[доставкой контента](phases/phase4/phase4_content_delivery.md) **без обновления самого
приложения** — то есть пользователь, который всё прошёл, о добавлении не узнает никак.
Лента новостей закрывает эту дыру и заодно даёт канал «что нового в версии».

### ⭐ Три канала доставки — объединены, но независимы (главное решение, 05.09.2026)

Новости **не отменяют и не заменяют** пуши и modal-баннеры. Каналов три, и у автора
**полная свобода комбинировать их как угодно** — в панели это одна форма отправки, где каналы
включаются галочками, а не три разных раздела:

| Канал | Что это | Живёт | Правится после отправки |
|---|---|---|---|
| **Новость** | пост в ленте «Новости» | ~2 месяца | да (текст, картинка) |
| **Modal-баннер** | перебивает вход в приложение | 24 ч (общий) / до прочтения (персональный) | да, пока активен |
| **Push** | системное уведомление в шторке | разовое событие | **нет — ушло значит ушло** |

Любая комбинация допустима, и все они — реальные рабочие сценарии:
- новость **+ пуш** — «добавил новые карточки», самый частый случай;
- **только новость** — мелочь, будить людей незачем (тихо, найдут сами);
- новость **+ баннер + пуш** — крупное событие (вышла большая тема, запуск фичи);
- **только баннер** — инфа на один вход, в ленту её тащить незачем (техработы сегодня);
- **только баннер, персонально** — бан/предупреждение конкретному пользователю;
- **только пуш** — короткое «вернись, стрик горит», без записи где-либо.

⚠️ **Каналы не связаны текстом.** У каждого своя длина и своя природа, поэтому в форме
отправки — **своё поле на канал**, а не один текст, размноженный в три места: пуш — строка,
баннер — короткий текст (+ картинка, см. ниже), новость — сколько нужно. Общая у рассылки
только запись в истории панели: «что я отправил, куда и когда».

⚠️ **Картинка.** Баннер и пост должны уметь нести **картинку** — иначе объявление о новой теме
выглядит скучной простынёй. Хранение (то же объектное хранилище, что и контент) и точный вид
блока — **TBD, продумываем при реализации**. Пуш — без картинки (текст, максимум иконка).

⚠️ **Визуальная часть — сознательно отложена.** Как это выглядит красиво (вёрстка баннера
с картинкой, карточка поста в ленте, вид формы в панели) — отдельная проработка перед
реализацией, здесь фиксируем только механику и свободу комбинаций.

⚠️ **Перекрёстные ссылки между каналами:** если у рассылки есть и баннер, и пост — у баннера
кнопка «Подробнее» ведёт в ленту к этому посту; если есть пуш и пост — тап по пушу открывает
ленту и подсвечивает пост. Если поста нет — пуш просто открывает приложение.

**Точка входа** — кнопка **«Новости»** во вкладке «Меню», отдельный полноэкранный route
(не диалог). На кнопке — **бейдж с числом непрочитанных**; после открытия ленты бейдж гаснет.

**Что на экране:**
- Список постов, новые сверху: заголовок, дата, тело поста, отметка «новое» у непрочитанных.
- Пост может быть длинным — раскрывается целиком в ленте (отдельного экрана поста не заводим).
- Пустое состояние: «Пока новостей нет».
- Нет сети → показываем закэшированные локально посты + строка «не удалось обновить».

**Прочитанность** — на клиенте: id прочитанных постов в DataStore (это не прогресс обучения,
переносить на новое устройство не обязательно; сервер о прочтении не спрашиваем).

**Редактирование.** Пост можно **отредактировать** (опечатка, дополнение, замена картинки) и
**удалить** — изменения подтягиваются при следующем открытии ленты. Повторный пуш при
редактировании **не отправляется** (иначе правка опечатки разбудит всех); нужно разбудить
осознанно — отправляется новая рассылка.

**Хранение.** Посты живут на сервере ~2 месяца, потом перестают отдаваться клиенту.
Пишутся руками из веб-панели администратора.

## Векторные анимации (Lottie) — общая механика приложения 🔜 БЛИЖЕ К РЕЛИЗУ

> Статус: **план, зафиксирован 05.09.2026.** Выросло из вопроса «как делать картинки в баннерах»
> и оказалось шире: это не деталь баннера, а **общий механизм оформления**, который потом
> пойдёт по всему приложению.
>
> ⚠️ Черновик направления, не жёсткая спека — детали при реализации изменятся.

### Что это и зачем именно вектор

Анимация приезжает **файлом** (Lottie — JSON, выгруженный из редактора), а проигрывает его код
приложения, написанный один раз. Отсюда главное свойство: **новые анимации ставятся и
удаляются по воздуху, без обновления приложения.**

Почему вектор, а не картинка/видео: весит 20–100 КБ, масштабируется на любой экран без мыла,
цвета задаются параметрами (значит попадают в нашу палитру), формат кросс-платформенный
и зрелый — фактический стандарт индустрии.

⛔ **Скриншоты экранов приложения — отменены** (решение 05.09.2026). Они устаревают при первой
же смене дизайна, нечитаемы в мелком размере и всегда выглядят инородной наклейкой. Нужно
показать кусок интерфейса — **рисуем его вектором** как стилизацию, а не снимаем экран.

### Где живёт — сейчас и потом

**Сразу (вместе с новостями и баннерами):**
- **Modal-баннеры** — иконка/анимация над текстом (крест при бане, колокольчик при техработах).
- **Посты в ленте «Новости»** — иллюстрация к посту: стилизованный кусок нашего интерфейса
  с подсветкой того места, где появилась новая фича.

**Потом, по мере развития (⚠️ ЭТО ОТДЕЛЬНЫЙ ЭТАП — см. пометку ниже):**
- **Сезонное оформление профиля** — зимой падают маленькие снежинки, летом светит солнце.
- **Экран завершения карточки** — разные анимации, вводим постепенно.
- **Стрик +1 день** — своя анимация на засчитанный день.
- **Завершение микротемы** — анимация на закрытие темы.

> ⚠️⚠️ **ПОМЕТКА НА БУДУЩЕЕ (обязательно перечитать, когда дойдём до этого шага).**
> Куда именно встраивать анимации в само приложение — **тщательно продумать отдельно**, а не
> лепить по ходу. Список выше — это идеи, а не утверждённые места. Продумать разом: где
> анимация усиливает момент, а где превращается в шум; что играет каждый раз, а что редко;
> не мешает ли это темпу прохождения (человек проходит по 5 микротем в день — то, что радует
> на первой, бесит на пятой). Отдельная проработка перед реализацией.

### Правила (чтобы это не развалилось)

1. **Медиа без фона и без текста внутри.** Присылаем прозрачную анимацию — фон, скругления,
   отступы, заголовок и кнопку рисует приложение своими токенами (`Color.kt`, `Dimens`).
   Тогда всё автоматически сочетается и **переживает смену дизайна**, заложенную в `CLAUDE.md`.
   Текст внутри вектора убил бы перенос строки, системный размер шрифта и правку опечатки.
2. **Анимация — украшение, а не сообщение.** Не загрузилась (нет сети, битый URL, старая
   версия клиента) → элемент показывается без неё: без дыры, без пустого квадрата, текст
   читается сам по себе. **Фолбэк на чистый текст обязателен везде.**
3. **Потолок 300 КБ** на файл. Иначе догружается дольше, чем на неё смотрят.
4. **Сдержанность по контексту.** В баннере бана — короткая, без зацикливания: текст там
   юридически значимый (причина, апелляция), прыгающий крестик читается издевательски.
   Долгие лупы на весь экран — жрут батарею и раздражают.
5. **Уважать системное «отключить анимации».** Android даёт это узнать — в этом случае
   показываем первый кадр статикой.
6. **Удаление по воздуху.** Анимация устарела/разонравилась → снимается с раздачи, клиент
   переходит на фолбэк сам. Это требование к серверной части, не «потом придумаем».

### Как делаем — рабочий процесс

Рисовать вручную ничего не нужно, инструментов учить тоже:

1. **Готовое из библиотеки LottieFiles** — 80% случаев (крест, галка, колокольчик, конфетти,
   снежинки, солнце). Ищу через MCP-поиск по библиотеке, беру, перекрашиваю под `Accent`.
2. **Своё — через Lottie Creator MCP.** Ставится одной командой:
   `claude mcp add lottiefiles-creator -- npx -y @lottiefiles/creator-mcp@latest`
   (нужен Node.js 18+, открытая вкладка LottieFiles Creator, включённый MCP в её настройках).
   Дальше Claude строит сцену прямо в редакторе — слои, фигуры, ключевые кадры, тайминги, —
   пользователь видит результат вживую на экране и правит на ходу. Экспорт → Lottie JSON.
   ⚠️ Мост требует открытой вкладки Creator, то есть работает только в живой сессии вдвоём.
3. **Экспорт → объектное хранилище → URL** в баннере/посте (или в каталоге анимаций
   приложения, если это встроенная анимация).

⚠️ Реальный потолок инструмента: геометрия интерфейса, иконки, частицы, подсветки — делается
отлично. Живая органика и персонажи — нет; они нам и не нужны.

⚠️ **Предпросмотр в панели обязателен** — грузишь JSON и сразу видишь баннер/пост таким,
каким его увидит пользователь: в наших цветах, с нашей рамой. Без этого отправка вслепую.

### Как это подключено — архитектура (обсуждено 05.09.2026)

Общая идея: **в коде расставлены точки вызова (слоты), они не знают ни про какие анимации.**
Код в момент события просто сообщает «случилось `CARD_DONE`». Дальше общий механизм смотрит
в каталог: есть ли что-то на этот слот, подходит ли по условиям, скачано ли — и играет либо
молча не делает ничего. Слоты живут в коде и меняются редко, наполнение живёт на сервере
и меняется когда угодно. Отсюда и берётся доставка по воздуху.

Три уточнения к этой картине — они и есть разница между «работает» и «работает через три года»:

**1. Не шина событий, а состояние.** Глобальная шина («кто угодно кидает событие, кто угодно
ловит») — известная ловушка: невозможно проследить, кто что вызвал, появляются гонки и утечки.
У нас проще: ViewModel и так знает, что карточка завершена, — он кладёт в свой UI-state поле
«сыграть слот `CARD_DONE`», а экран рендерит общий компонент. Точка подключения = одна строка
в уже существующем месте, без отдельной инфраструктуры.

**2. Ровно ОДИН компонент знает слово Lottie.** Проигрыватель — единственный файл в
`ui/components/`, куда импортируется библиотека. Тогда замена библиотеки, общий фолбэк, учёт
системного «отключить анимации» — правятся в одном месте, а не по всем экранам (Правило №0).

**3. ⚠️⚠️ Анимация НИКОГДА не в критическом пути.** Из формулировки «код проходит через точку»
легко случайно вывести, что поток исполнения идёт *сквозь* анимацию — и получить приложение,
где прогресс не записался, потому что не скачался JSON, или переход к следующей карточке ждёт
конца конфетти. Правильно наоборот: бизнес-логика отработала и поехала дальше, анимация —
независимый слой поверх. Нет сети, битый файл, незнакомый слот, анимации выключены в системе →
не меняется **ничего**, кроме отсутствия красивости. Это та же мысль, что уже стоит в
`CLAUDE.md`: продвижение логики не зависит от того, доживёт ли `LaunchedEffect` до конца.

**4. Слоты ставим только туда, где осознанно решили.** Соблазн «навешаем точек везде, вдруг
пригодится» даёт десятки мёртвых крючков, которые через год никто не помнит и боится трогать.
Список слотов короткий, закрытый, пополняется решением — не впрок.

### Два класса анимаций по жизненному циклу

Ключевое различие, найденное в обсуждении: **ради разовой анимации в баннере нет смысла
что-то класть в постоянный каталог** — приехала с рассылкой, отыграла, ушла вместе с ней.

| | **Каталожные** (переиспользуемые) | **Одноразовые** (при рассылке) |
|---|---|---|
| Примеры | завершение карточки · стрик +1 день · завершение микротемы · снежинки в профиле зимой, солнце летом | красный крест в баннере бана · иллюстрация к посту о новой фиче |
| Откуда | каталог анимаций (`catalog.json`) | приезжает вместе с баннером/постом |
| Кэш | долгий, скачивается заранее | временный |
| Смерть | убрана из каталога → уборка сносит файл | пользователь закрыл баннер / истёк TTL рассылки |

Формат файла и проигрыватель у обоих классов **одинаковые** — различается только жизненный цикл
и кто отвечает за удаление.

### Выбор анимации, когда их несколько на одно событие

Задача настоящая: одинаковая анимация на каждой завершённой карточке приестся к третьему дню,
поэтому на слот нужно уметь вешать несколько вариантов.

⚠️⚠️ **ГЛАВНЫЙ РИСК И ГЛАВНОЕ ПРАВИЛО.** Начинается с «выберем по условию», а через год в
клиенте живёт нечитаемый движок правил, который нельзя ни протестировать, ни починить по
воздуху — он в коде на телефонах у людей. Поэтому условия в каталоге **декларативные и
примитивные, ровно четыре ручки, больше не заводить**:

- `slot` — куда играет;
- `weight` — вес для случайного выбора (несколько вариантов → берём случайную по весам, вот и
  разнообразие);
- `from` / `to` — окно показа (снежинки только зимой, солнце летом);
- `minAppVersion` — не отдавать тем, кто не умеет её показать.

Алгоритм тогда в одну строку: **отфильтровать по условиям → случайный выбор по весам → играть.**
Никаких «если стрик больше семи и вторник». Понадобится сложное условие — **решает сервер** и
отдаёт клиенту уже отфильтрованный список. Клиент остаётся тупым, и это осознанно.

### Кэш, замена, уборка

- **Замена — это новый файл, а не перезапись.** Не класть новую анимацию по старому URL: у людей
  и в кэшах останется старая, и будешь ловить призраков. Имя версионируем (`card_done_v2.json`),
  в каталоге меняется ссылка — вот и вся замена.
- **Удаление обязано убирать файл с диска.** Пропала из каталога и не привязана к живой
  рассылке → сносится при ближайшей уборке. Плюс потолок кэша с вытеснением старого. Иначе за
  год накопится помойка из анимаций, которых человек больше не увидит, и это станет жалобой
  «приложение весит гигабайт».
- **Качаем заранее, показываем только готовое.** Каталожные — тихо подтягиваются при обновлении
  каталога (лучше на Wi-Fi). Баннерные — до показа баннера. Жёсткое правило: **пустого места в
  ожидании загрузки не бывает** — либо файл готов и анимация играет, либо элемент показывается
  без неё. Никаких дыр и спиннеров вместо украшения.
- **Битый файл — не падение.** Закачка обрывается на потолке 300 КБ, не распарсилось → тихий
  фолбэк. Хранилище наше, но клиент не должен уметь падать от мусора.
