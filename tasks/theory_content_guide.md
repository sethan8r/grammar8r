# Theory Content Guide — Grammar8r

Правила и принципы написания теоретического контента.  
Читать перед написанием любой новой микротемы.

**Связанные документы:**
- [`exercise_templates.md`](phases/phase1/exercise_templates.md) — форматы всех 14 типов упражнений + DB-схемы
- [`grammar8r_plan.md`](grammar8r_plan.md) — структура курса, список тем и микротем (**здесь смотреть ЧТО писать следующим**)

## 1. Как работают ID

### Type-specific ID (реальные DB-идентификаторы)

Каждый тип упражнения нумеруется **независимо от 1**. `WordArrangement(id=1)` и `TrueFalse(id=1)` — разные упражнения, конфликта нет.

ID уникален внутри своего типа. Именно этот ID пишется в `CardExerciseIndex` и используется в БД. Это единственные ID которые имеют значение для приложения.

### Глобальный Ex N (только навигация)

`**Ex 47 · TrueFalse**` — номер 47 нужен только чтобы читать файл и ссылаться на упражнение в разговоре. В БД не хранится. Может быть непоследовательным из-за реорганизации карточек — это нормально.

### AI Exercise ID

Строковый, не числовой: `basics_card{N}_ex1` где N — номер карточки.  
Пример: карточка 29 → `basics_card29_ex1`. Числовой счётчик для AI не ведётся.

### Где живут счётчики

В конце каждого theory-файла — таблица со значениями **последнего использованного ID** по каждому типу. Перед написанием нового блока — прочитать эту таблицу и продолжить с "Следующий" значений. После написания — обновить таблицу.

## 2. Структура theory-файла

### Что писать дальше

Список микротем и их порядок — в `grammar8r_plan.md` → раздел структуры соответствующей темы. Перед написанием: найти последнюю написанную микротему в файле и взять следующие по списку.

### Блоки

Каждые 3 микротемы оборачиваются в блок:
```
# БЛОК N · Микротемы X–Y
```

### Микротема

```
## Microtopic N — Title EN · Title RU

**ID:** N | **Order:** N

---

[карточки]

### Words8r Sync · Название раздела
| Слово | Переводы | Транскрипция |
```

### Карточка

```
### Card N · Название карточки

**ID:** N | **Order:** N

#### Theory
[теория]

#### Summary *(кнопка «?» в упражнениях)*
[2–3 предложения — краткий конспект правила]

#### Examples
| # | RU | EN |
|---|----|----|
| N | Русский пример. | English example. |

---

#### Exercises
[упражнения]

---

#### AI Exercise
[AI упражнение]

#### Clarification Options
- Вопрос 1?
- Вопрос 2?
- Вопрос 3?

---
```

### Карточка без упражнений

Иногда карточка содержит только теорию — без упражнений. Это нормально для справочных карточек (например, "Почему дни пишутся с заглавной"). В таком случае секция `#### Exercises` опускается, но `#### Clarification Options` остаётся.

## 3. Правила теории

### Главный принцип: объяснять, а не называть

Плохо: *"Несчётные существительные не имеют множественного числа."*  
Хорошо: *"Представь что advice — это не штука, а вещество. Как воду нельзя посчитать ('три воды' звучит странно), так и advice нельзя: 'three advices' — ошибка. Можно только 'three pieces of advice'."*

Пользователь после каждой карточки должен думать **"О, вот оно что!"** — а не "ещё одно правило".

### Объяснять через сравнение с русским

Не просто "в английском так", а почему это логично и откуда берётся ошибка у русскоязычного.

Шаблон объяснения:
1. Как это работает в русском (что привык делать пользователь)
2. Почему английский работает иначе
3. Конкретная ловушка которая из этого вытекает

Примеры:
- *"По-русски 'я знаю' и 'я знал' — один глагол с разным окончанием. В английском это два разных слова: know и knew. Мозг хочет добавить -ed к know — не выйдет."*
- *"По-русски 'мне холодно' — от ощущения. По-английски 'I am cold' — от субъекта. Дословный перевод 'to me cold' — бессмыслица."*

### Разжёвывать максимально подробно

Одно правило — одна карточка. Нюанс внутри правила — отдельная карточка.  
Лучше 3 понятные карточки чем 1 перегруженная.

Каждое утверждение подкрепляется примером. Каждое исключение объясняется — не просто "запомни", а почему оно такое.

Если есть логика даже за исключением — объяснить её:  
*"Почему 'at night', а не 'in the night'? Ночь воспринимается как особый момент темноты, а не период с чёткими границами — отсюда точечный 'at'."*

### Переводить все английские примеры

**Сейчас (начало курса, пользователь не знает английского):** переводить абсолютно всё — каждое слово, каждую фразу, каждое предложение.

> ⚠️ Ближе к середине курса, когда база накоплена, переводы в упражнениях могут убираться. Делать это только по явной команде. Пока команды не было — всегда переводить.

Форматы перевода:
- В таблице Examples: отдельная колонка RU
- В тексте теории: курсив или скобки после примера

```
"I have been waiting for an hour." — *Я жду уже час.*
walk over a hill *(подняться на холм и спуститься)*
```

### Ловушки — конкретно

Каждая ловушка: сломанный пример ✗ + правильный вариант ✓ + объяснение почему.

```
"I need an advice." ✗ → "I need some advice." ✓  
advice — несчётное, артикль a/an с ним невозможен.
```

Не писать просто "это ошибка" — писать откуда берётся ошибка.

### Clarification Options — что это

Заранее написанные вопросы для фичи "Не совсем понял" в конце каждой карточки. Пользователь тапает на вопрос → он уходит в AI → AI объясняет то же правило другими словами и с другим примером (не повторяет теорию карточки).

Писать 2–3 вопроса которые реально могут возникнуть у пользователя после прочтения карточки. Не общие ("расскажи про это правило"), а конкретные ("Почему 'at night', а не 'in the night'?").

### Разнообразие имён в примерах

Чередовать: Дима, Лена, Игорь, Катя, Рома, Саша, Вера, Тёма, Оля, Коля, Миша, Ира.  
Не повторять одно имя несколько раз подряд в одной карточке. Максим и Анна — избегать.

### Живые примеры

Примеры из реальной жизни, а не учебниковые. Не "The cat is on the mat" — а ситуации которые пользователь узнаёт:
- рабочий чат, кофейня, поездка, телефонный разговор
- эмоции, планы, бытовые действия

## 4. Упражнения

### Главный источник правил

**→ [`exercise_templates.md`](phases/phase1/exercise_templates.md)**

Там: форматы всех 14 типов, DB-схемы, правила explanation.

### Формат заголовка упражнения

```
**Ex N · [Точное имя типа]** *(ID: X)*
```

Имя типа — **точно как в таблице счётчиков** в конце theory-файла:

`WordArrangement` · `MultipleChoice · CHOICE` · `MultipleChoice · FORWARD_CHOICE` · `MultipleChoice · REVERSE_CHOICE` · `TrueFalse` · `ErrorCorrection` · `TextInput` · `Matching` · `Transformation` · `Categorization` · `TableFill` · `FindTheOdd` · `ConstructionMeaning` · `DialogRestore`

Примеры правильных заголовков:
```
**Ex 47 · TrueFalse** *(ID: 26)*
**Ex 48 · MultipleChoice · FORWARD_CHOICE** *(ID: 40)*
**Ex 49 · WordArrangement** *(ID: 27)*
```

### TrueFalse — формат утверждений

Каждое утверждение — **реальное предложение на английском** (+ русский перевод), часть из которых содержит грамматическую ошибку. Пользователь сам определяет: правильно или нет.

**Запрещено** писать мета-утверждения вроде `"Please" is a correct answer to "Thank you."` или `"Many" is used with uncountable nouns.` — это не тест на понимание грамматики, а тест на знание правил в абстракции. Вместо этого — конкретное предложение, которое либо грамматически верно, либо содержит ошибку:

❌ Плохо: `"I have some good news." is correct.`
✓ Хорошо: `I have some good news.` — *У меня есть хорошие новости.* — ✓

❌ Плохо: `"Please" is a correct answer to "Thank you."`
✓ Хорошо: `— Thank you! — Please.` — *— Спасибо! — Пожалуйста.* — ✗

### Ключевые правила кратко

**1 вопрос = 1 упражнение** для типов: `MultipleChoice · CHOICE`, `MultipleChoice · FORWARD_CHOICE`, `MultipleChoice · REVERSE_CHOICE`, `ErrorCorrection`, `ConstructionMeaning`, `DialogRestore`, `FindTheOdd`.

Упаковка нескольких вопросов в один `Ex N` — ошибка. Каждый вопрос получает свой `Ex N` и свой type-specific ID.

**Разнообразие обязательно.** На одну карточку — разные типы. Не делать подряд 3 MultipleChoice. Использовать менее частые типы: `Transformation`, `Categorization`, `FindTheOdd`, `Matching`, `ConstructionMeaning`, `DialogRestore` — они дают разные форматы взаимодействия.

**Прогрессия сложности:** в рамках одной карточки сначала выбор (CHOICE/FORWARD_CHOICE), потом ввод (TextInput/WordArrangement).

**Варианты** — только в формате:
```
- Вариант
- **Правильный вариант** ✓
- Вариант
```
Никакого `a) ... ✗ / b) ... ✓`.

**Дистракторы** — реалистичные ошибки, не абсурд. Дистрактор должен быть именно той ошибкой которую реально совершает русскоязычный.

### ErrorCorrection vs FORWARD_CHOICE — критичное различие

**ErrorCorrection** — условие задания содержит только **сломанное английское предложение**, без русского перевода.  
Пользователь читает EN и находит ошибку.

**FORWARD_CHOICE** — условие задания содержит **русское предложение** (или русский контекст), пользователь выбирает правильный EN вариант.

> Правило: если для понимания задания нужен русский контекст → FORWARD_CHOICE. Если ошибка видна из самого EN предложения → ErrorCorrection.

Никогда не добавлять русский перевод в условие ErrorCorrection — это нарушение формата.

### TrueFalse — детали формата

Всегда ровно **5 утверждений**. Обязательно минимум **2 верных** и **2 неверных** (пятое — любое).

**Сейчас (начало курса):** таблица с тремя колонками — EN, RU-перевод, Верно?:
```
| # | EN | RU | Верно? |
|---|----|----|--------|
| 1 | He go to work every day. | Он ходит на работу каждый день. | ✗ |
```

> ⚠️ Ближе к середине курса колонка RU может убираться — делать только по явной команде.

### WordArrangement — тире для знакомых слов

Слово считается **знакомым** если оно уже было дано к изучению и добавлено в словарь в Words8r Sync предыдущих карточек этого же файла.

В таблице слов: знакомые слова получают `—` вместо перевода (пользователь тапает на слово в приложении и получает перевод). Новые слова — полный перевод.

```
| Слово     | Перевод          | Лишнее? |
|-----------|------------------|---------|
| jumped    | прыгнул          | —       |  ← новое слово
| the box   | —                | —       |  ← знакомое слово
| into      | в (внутрь)       | ✗       |  ← дистрактор (новое)
```

## 5. AI упражнения

**Главный источник:** `grammar8r_plan.md` → раздел "AI-упражнения — модель данных и флаги"

### Обязательные поля

```
**ID:** basics_card{N}_ex1
**Title:** "Глагол + объект"
**Input Mode:** FREE_WRITE / FILL_BLANKS
**Words Source:** NONE
**AI Config Profile:** EXERCISE_LIGHT
**User Instruction:** "Что делать пользователю — без технических деталей"
**Prompt Template:** "... Пример вывода AI: 'конкретный текст'"
```

### Критичные правила

- `User Instruction` — только что делать. Без слов "AI", "FILL_BLANKS", технических деталей.
- `Prompt Template` **обязательно** заканчивается строкой `Пример вывода AI: '...'` с реальным примером текста который AI выдаст пользователю. Без этого нельзя проверить корректность задания.
- Ошибки AI объясняет **по-русски**, кратко, конкретно.
- `Words Source: NONE` для предтемы "Основы" (слов ещё мало). `GENERAL` — для тем где слова уже накоплены.
- `FILL_BLANKS` — когда AI присылает текст с пропусками `[___]`. `FREE_WRITE` — всё остальное.

## 6. Words8r Sync

В конце каждой **микротемы** (не карточки) — таблица слов для добавления в словарь:

```
### Words8r Sync · Краткое название

| Слово | Переводы | Транскрипция |
|-------|----------|-------------|
| word  | перевод  | [транскрипция] |
```

Включать: ключевые слова микротемы которые пользователь должен запомнить.  
Не включать: служебные слова уже изученные в предыдущих микротемах.

## 7. Чеклист перед вставкой в файл

- [ ] Прочитана таблица счётчиков в конце файла — все ID продолжают с правильных значений
- [ ] Глобальные `Ex N` идут последовательно внутри блока
- [ ] Ни один `Ex N` не содержит более 1 вопроса (для типов с 1-вопросным форматом)
- [ ] Все английские примеры в теории переведены
- [ ] Все варианты в упражнениях в формате `- Вариант` / `- **Правильный** ✓`
- [ ] В ErrorCorrection нет русского перевода в условии
- [ ] В TrueFalse ровно 5 утверждений, минимум 2 верных и 2 неверных
- [ ] Каждый AI Exercise заканчивается строкой `Пример вывода AI: '...'`
- [ ] Таблица счётчиков в конце файла обновлена после добавления блока
